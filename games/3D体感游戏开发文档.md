## 一、项目概述

浏览器 3D 网页游戏，无需安装客户端：

- **电脑端（主机）**：打开 `http://localhost:3000/`，渲染 3D 战场并运行游戏逻辑；可通过摄像头 + MediaPipe Pose 识别人体左右移动，控制战机平移，也可切换为键盘控制。
- **手机端（控制器）**：扫描电脑端二维码打开 `controller.html`，横屏双拇指操作（左机炮/中干扰弹条/右导弹），并实时显示护甲、导弹余量、倒计时、得分与剩余目标。**V2.5.2 起**右上角新增「菜单」：连接电脑端后可在手机上返回战场选择、直接选模式出击，结算时也可在手机端重玩本局/返回选模式，无需回到电脑。
- **服务端**：Node.js + Express + Socket.IO，负责静态托管、二维码、主机与手机之间的指令/状态转发，仅需局域网。

V2 把玩法从单一练靶升级为**四种战场的限时歼灭战**：不同地图、不同敌军编成、敌方会开火、玩家有机炮与导弹两种武器、按目标体型计分并限时结算。

## 三、技术栈与总体架构

| 层 | 技术 |
|---|---|
| 3D 渲染 | Three.js 0.160（多 CDN 动态 import，失败自动回退） |
| 姿态识别 | MediaPipe Pose 0.5.1675469404（CDN，本地推理，画面不上传） |
| 前端组织 | 原生 ES Module，无打包工具，浏览器直接加载 `src/*.js` |
| 服务端 | Node.js + Express + Socket.IO |
| 二维码 | `qrcode` npm 包，服务端生成 DataURL |
| 通信 | Socket.IO（WebSocket 优先，轮询回退） |

数据流：

```
摄像头 → MediaPipe Pose（仅肩 11/12 + 髋 23/24）→ 体感飞行 3 信号（shift/torso/squat）
                              ↓
键盘 A/D · W/S · Z/X ──→ 玩家战机 平移 / 俯仰 / 机头方位
                              ↓
手机控制器 ──weapon──→ 服务端 ──weapon──→ 电脑主机（开火）
电脑主机 ───state───→ 服务端 ───state───→ 所有手机（状态同步）
```

## 四、运行方式

```bash
# 项目根目录
npm install
npm start          # 等价于 node server.js，默认端口 3000
```

- 电脑游戏页：`http://localhost:3000/`
- 手机控制器：扫描页面二维码，或直接访问 `https://<电脑局域网IP>:3443/controller.html?v=<版本号>`
- 电脑与手机必须连接同一 WiFi；服务端同时监听 `0.0.0.0:3000`（HTTP，给电脑主机）与 `0.0.0.0:3443`（HTTPS，给手机）
- 健康检查：`GET /health`；控制器信息与二维码：`GET /api/info`（返回 `secure` 字段与 HTTPS 地址）
- **手机体感必须走 HTTPS（V2.3.3）**：Chromium 内核（华为浏览器、Chrome、Edge、微信 X5）只在安全上下文派发 `deviceorientation/devicemotion`，HTTP 局域网 IP 不属于安全上下文，传感器完全静默。服务启动时自动生成自签名证书到 `certs/`（可用 `HTTPS_PORT` 环境变量改端口），手机首次打开会提示证书不受信任，点「高级 → 继续访问」后即可正常读取姿态。微信内置浏览器通常会直接拒绝不受信证书，此时可改用华为/系统浏览器打开同一个 HTTPS 地址；电脑主机页仍用 `http://localhost:3000/`（localhost 本身属于安全上下文，摄像头不受影响）。
- 华为手机浏览器/相机无扫码入口时，可用微信「扫一扫」打开二维码（已实测可用）

首次选择「摄像头姿态」会请求摄像头权限；权限处理与姿态启动**不阻塞回合开始**，倒计时会立即进行。无法授权时可在菜单切换「键盘 A/D」。

### 5.2 胜负条件

- **胜利**：在限时内击毁全部敌方目标（`remaining = 0`）。
- **失败**：倒计时归零仍有残余目标；或玩家战机被击毁（立即失败）。
- 结束即进入结算面板，可「重玩本模式」或「返回模式选择」。

### 5.3 玩家生存规则

| 情况 | 结果 |

| 炮弹命中后的无敌帧 | 0.55s 内不再受伤 |
| 开局状态 | 护甲 3 格、导弹 10 发、分数 0 |

## 六、操作方式

### 6.1 电脑端

| 操作 | 功能 |
|---|---|
| 重心左右平移（V2.6.0） | 髋部中点横向偏移 → **压坡度左右转弯**：偏离中心越远转向越大，到边界饱和；死区 0.06、饱和 0.28（肩宽归一化） |
| 躯干前俯 / 后仰（V2.6.0） | 肩髋 z 差 → 俯仰：前俯 = 俯冲（最大 −31°），后仰 = 爬升（最大 +24°）；死区 0.10、饱和 0.45 |
| 屈膝下蹲（V2.6.0） | 髋部下沉 ≥ 0.18（肩宽归一化）并保持 0.2s → 0.6s 紧急急俯冲规避，冷却 2s；期间平移/俯仰/开火不锁死 |
| A / D 或 ← / → | 键盘平移（按住持续生效） |
| W / ↑（V2.3.0） | 抬头爬升（俯仰角最大约 +24°） |
| S / ↓（V2.3.0） | 俯冲下降（俯仰角最大约 −31°） |
| Z / X（V2.3.0） | 机头左 / 右方位角（持续转动 ±40°，不自动回中） |
| Q（按住） | 机炮连射（16 发/秒，左右机炮口交替） |
| E（单击）（V2.3.0） | **双发导弹**：机腹左右各偏移约 2.2 单位、方向外偏 ±2.5°，消耗 2 发；仅剩 1 发时单发并提示 |
| F（单击）（V2.3.0） | **双发干扰弹**：左右各偏移约 2.5 单位，无限余量、仅共享 2.5s 冷却 |

#### 体感飞行（V2.6.0：三通道，双手握手机场景定稿）

硬性约束：双手**持续横握手机在胸腹前**，手腕/手掌关键点被遮挡，因此识别**只用肩 11/12 与髋 23/24**，禁止使用 15/16；手机只负责机炮/导弹/干扰弹，体感与开火相互独立。菜单控制方式仍为「体感飞行 / 键盘」。

| 人体动作 | 信号（`pose.js`） | 飞控含义 |
|---|---|---|
| 重心向左 / 向右平移 | `shift` | 压坡度左 / 右转弯（偏离越远转向越大，边界饱和） |
| 躯干向前俯身 / 向后仰身 | `torso` | 俯冲 / 爬升 |
| 屈膝下蹲（保持 ≥0.2s） | `squat` | 紧急急俯冲规避（0.6s，2s 冷却） |

- **识别优先级**：重心平移（最高）> 躯干俯仰 > 蹲起立；平移与俯仰可同时叠加，实现转弯爬升、转弯俯冲。
- **移除项（V2.6.0）**：删除手臂通道（`armRelY/armRelX` 及双臂抬放/左右移）、鼻尖转身（原地偏航）、肩宽前后走（Z 轴前进/后退）与键盘 R/T 接近逻辑；飞机只保留左右转向 + 爬升/俯冲，无油门、无前进后退。
- **视角锁定**：开局选定第一/第三人称后全程锁定，战斗中按 V 只提示「视角已锁定」，不再切换。
- **校准**：距摄像头约 2~3 米、全身肩与髋入镜；进入出击检查或每局开始时站直、重心居中保持约 1 秒采样零点。
- **容错**：死区 + 0.28 指数平滑（等效移动平均）+ 转向饱和上限；人体完全移出画面超过 0.9s 视为丢失，俯仰/转向输入归零、姿态平缓回正，禁止剧烈突变。
- **下蹲规避**：仅在战斗中生效；保持达标 0.2s 触发（过滤膝盖抖动），规避 0.6s 内强制急俯冲，玩家仍可平移、俯仰、开火；2s 冷却内下蹲按普通蹲姿处理，起立即回常规操控。
- 训练屏 5 道题：左转 / 右转 / 俯冲 / 爬升 / 规避，练什么、打什么完全一致。

- 输入优先级：**键盘 > 摄像头姿态**；键盘对应轴无操作时才使用摄像头姿态数据。
- 摄像头姿态是**绝对目标**：重心偏移决定转向角、躯干倾角决定俯仰角，回到立正/居中即回中；每局开始重新采样基准（约 1 秒）。
- 俯仰与方位角为持续状态：键盘松开后俯仰平滑回 0，方位角保持当前角度；高度由俯仰积分产生（`sin(pitch) × 26/s`），上下限沿用 ±14 与地形安全高度。
- 机炮与导弹均沿**机头前向**（含俯仰与方位角）发射，因此俯冲可打击地面目标。
- 姿态识别约 15fps；重心偏移映射为 −1..1 横向输入（18/s）并叠加机身滚转（最大 ±0.36 rad），平滑到 ±100 战场边界。
- 超过 0.9s 未识别到人体时视为丢失：俯仰/转向输入归零，俯仰与方位角按指数曲线**平缓回正**（无跳变），不会锁定在丢失瞬间的姿态。
- 窗口失焦会清空按键，避免持续开火卡住。
- 摄像头占用处理（V2.1.3）：启动前先强制释放本页残留旧视频流（`track.stop()`）；`NotReadableError`（被占用）自动间隔 700ms 重试 3 次，状态条显示「被占用，重试中…」；页面隐藏/关闭（pagehide/beforeunload）时立即归还摄像头；姿态识别失败切键盘模式时同步释放。注意：浏览器无法强制释放被**其他应用**（如微信视频、相机 App）占用的摄像头，此时提示用户关闭后刷新。

### 6.2 手机端（横屏双拇指控制器）

| 操作 | 功能 |
|---|---|
| 左侧机炮区按住 | 机炮持续开火，松开立即停止 |
| 中部干扰弹条点按 | **单发**干扰弹；数量无限、冷却 2.5s（与键盘 F 共用同一冷却），条上显示「∞」并在冷却期置灰 |
| 右侧导弹区点按 | **单发**导弹；本地冷却 1.5s，余量为 0 时禁用 |
| 右上角「菜单」 | 连接电脑端后打开战场列表直接选模式出击；结算时「重玩本局 / 返回选模式」 |
| 顶部状态条 | 模式（含难度简称）、倒计时、得分、剩余目标、护甲、导弹余量、连接状态 |

- V2.3.4 起手机端不再承担飞行控制，V2.4.3 起手机体感代码整体移除（`deviceorientation`/`devicemotion`/校准一并删除）；HTTP 页面即可正常开火，无需安装证书。
- 手机端武器均为单发，双发仅限键盘 E / F；体感飞行与开火完全独立。
- 布局为「左拇指机炮 / 中条干扰弹 / 右拇指导弹」，竖屏时显示横屏提示条。

**浏览器兼容性（V2.1.1）**：

- 输入事件采用 `onPress` 兼容层：优先绑定 `touchstart/touchend/touchcancel`，同时保留 Pointer Events 与鼠标回退，用时间戳对同一手势的跨事件源重复触发去重（Chrome 会先派发 `pointerdown` 再派发 `touchstart`）。解决微信内置浏览器（X5 内核）与部分国产浏览器 Pointer Events 不完整导致的「点击不发射」。
- 全局兜底释放新增 `touchend/touchcancel/mouseup`，防止任何内核下机炮卡在按住状态。
- 布局沿革：V2.1.2 竖屏（上机炮下导弹）→ V2.4.3 起改为横屏双拇指（左机炮/中干扰弹/右导弹），竖屏时仅显示横屏提示条。

### 7.1 玩家机炮

### 7.3 干扰弹（V2.2.0）

| 参数 | 值 | 说明 |
|---|---|---|
| 数量 | 无限（V2.2.1 起） | `CFG.flare.count = Infinity`，不消耗、局内不重置 |
| 冷却 | 2.5s | `CFG.flare.cooldown`，成功释放后开始计时 |
| 吸引半径 | 130 | `CFG.flare.radius` |
| 诱饵存活 | 1.0s | `CFG.flare.life` |

**数量限制**

- 干扰弹**无限**，唯一限制是 2.5s 冷却（V2.2.1 由「每局 5 枚」改为无限）。
- 释放不扣减数量，也不存在「已耗尽」状态；HUD 与手机端显示「x∞ / ∞」。
- 若后续要改回限量，只需修改 `CFG.flare.count` 为具体数值，扣减与耗尽逻辑仍保留（`Number.isFinite` 判断）。

**冷却规则**

- 冷却 2.5s 从**成功释放那一刻**开始倒数，被拒绝的触发（冷却中/未开战）不会重置或延长冷却。
- 冷却由主机统一计时（`game.flareCd`），**键盘 F 与手机干扰弹条共享同一冷却**，不存在双端各算一套的情况。
- 冷却中触发无效，HUD 提示「干扰弹冷却中 X.Xs」；手机端同步显示冷却进度，本地先做一次 2.5s 节流以降低无效请求。
- 冷却只在 `PLAYING` 阶段递减，菜单/检查/倒计时/结算阶段暂停。

**释放效果**

- 键盘 F 或手机控制器干扰弹条触发；键盘 **F 一次双发**（V2.3.0，以机体位置为基准左右各偏移约 2.5 单位），手机端单发；在战机后方释放发光诱饵与火花粒子。
- 存活期间半径 130 内的敌方导弹改道追踪最近的诱饵，接触（距离 < 3.2）即引爆，复用现有爆炸特效与音效。
- HUD 生命面板显示「干扰弹 x∞」，手机端同步显示「∞」与冷却。

### 7.6 飞行姿态与机头射击（V2.3.0）

玩家新增两个持续角度状态，均由 `src/player.js` 维护：

| 状态 | 范围 | 回中 | 来源 |
|---|---|---|---|
| `pitch` 俯仰 | −0.55 ~ +0.42 rad（约 −31° ~ +24°） | 松开后以约 0.25s 时间常数回 0 | W/↑（+1）、S/↓（−1）、手机 beta、姿态肩高 |
| `yaw` 方位角 | ±0.70 rad（约 ±40°） | **不自动回中** | Z（+1，左）、X（−1，右）、手机 gamma |

**前向向量**（与 `group.rotation.order = 'YXZ'` 一致）：

```
forward = (-sin(yaw)·cos(pitch),  sin(pitch),  -cos(yaw)·cos(pitch))
```

**姿态可视化**：`group.rotation.x = pitch + 轻微 bob`、`group.rotation.y = yaw`、`group.rotation.z = 平移侧倾 + clamp(-yawIn × 0.15)`。

**高度积分**：`yOff += sin(pitch) × climbSpeed(26) × dt`，上限 +14、下限取 `max(-14, 6 - altitude)`；抬头爬升、俯冲下降，松开俯仰后高度保持在当前值。

**射击沿机头**：`game.shootCannon()` 使用 `player.gunWorld(side)` 与 `player.forward()`；导弹使用 `player.missileWorld()` 与 `player.forward()`，锁定预览也改用机头前向，因此俯冲时弹道指向地面目标。

**摄像机跟随方位**：`updateCamera` 的 lookAt 目标 x 叠加 `-sin(yaw) × 70`，相机位置也做约 18 单位的轻微横向跟随；高度沿用原有跟随逻辑。

**输入优先级**：键盘对应轴 > 摄像头姿态；键盘无输入时，重心偏移映射转向绝对目标、躯干倾角映射俯仰绝对目标（手机体感若未来启用则优先于摄像头，默认不参与）。

**摄像头姿态采集（V2.3.4 → V2.6.0）**：MediaPipe Pose 的 33 个关键点中只取左右肩（11/12）与左右髋（23/24），全部用肩宽归一化；腕/手（15/16）因手机遮挡明确剔除。

| 关键点 | 派生信号 | 用途 |
|---|---|---|
| 髋部中点 `(lh.x+rh.x)/2` 相对基准 | `shift = -(hipX - baseHipX) / 肩宽`（右=正） | 压坡度转弯 + 横向平移 + 机身滚转 |
| 肩/髋 z 差 `(肩z) - (髋z)` 相对基准 | `torso = (base - now) × 4`（前俯=正） | 俯仰绝对目标 |
| 髋部中点 y 相对基准 | `squat = (hipY - baseHipY) / 肩宽`（下沉=正） | 下蹲规避触发 |

- 关键点只用 11/12/23/24；**15/16（腕）与手部一律不参与**，适配双手横握手机被遮挡的场景。
- 基准：每局/每题前约 15 帧（≈1 秒）取平均后固定，回位即回中；三路信号都做 0.28 系数指数平滑。
- `torso` 用 z 差判断方向（前俯时肩比髋更靠近镜头），并 ×4 放大到可用量程；纯 2D 投影无法区分前后俯仰。
- 下蹲只取髋部下沉量，与左右重心、躯干俯仰解耦；`CFG.pose.squatStart=0.18`，保持 0.2s 触发。
- 人体丢失（>0.9s 或髋不可见）时三路输入归零，`pitchAbs/yawAbs` 传 null，俯仰平滑回中、机头不突变；HUD 提示「未识别到人体 · 请全身入镜」

**手机体感（V2.3.1 引入，V2.3.4 停用）**：代码保留。Chromium 系浏览器只在安全上下文派发 `deviceorientation`/`devicemotion`，局域网 HTTP 页面一律读不到数据，HTTPS 自签名证书在华为/微信等浏览器又常被直接拒绝，因此飞行控制改用摄像头；手机仅负责开火。

## 九、五模式地图与敌军布置

战场统一为 620×620 的地形网格，中心位于 z = −130；敌方可玩区域约 z −40 ~ −180、x ±90。玩家固定在 z = 0 上空悬停（V2.6.0 起移除 V2.5.0 的 R/T 纵向接近与 `zOff`，飞机只有转向与俯仰），导弹锁定角与机炮射程按该默认站位调校；训练场靶标已压缩到 z −40 ~ −160 以落入射程。

### 9.1 公路

- 高度场为低缓丘陵，叠加 S 形公路：`roadX(z) = 26·sin((z+100)·0.0105) + 10·sin((z+40)·0.026)`。
- 路面压平并绘制灰色公路带与白色虚线；两侧分布树木、岩石。
- 装甲车队沿公路曲线往返推进（z 方向 ±26 摆动，x 跟随公路），路边炮塔与终点地堡构成纵深防线。
- 玩家高度 24。

### 9.2 野战

- fbm 噪声生成起伏丘陵与山脊，坦克群藏在山谷、反斜面与树林间。
- 敌军分散在宽度更大的正面，炮塔与地堡位于高地。
- 玩家高度 38，视野更远。

### 9.3 海战

- 海面为 52×52 顶点网格动态波动，每 3 帧重算法线；水面高度约 y=0.12，地形整体下沉。
- 两座岛屿抬升地表，岛礁炮台部署在岛上；驱逐舰/护卫舰/快艇按编队巡航并留下尾迹。
- 玩家高度 14，贴近海面飞行。

### 9.4 空战

- 地面下沉至约 y=−45，仅作为远景；高空布置云层 Sprite 与敌机编队。
- 敌方战机按航线巡航、无人机绕圈、预警机大范围盘旋、地面雷达站旋转天线。
- 玩家高度 46，雾更远、天空更亮。

### 9.5 训练场（V2.3.0）

- 平缓起伏靶场（高度场仅 1.6~6 左右），纵向靶标线沿 z = −40 ~ −220 均匀分布。
- 固定 6 个地面目标：炮塔 ×4 + 地堡 ×2，左右交替布置在靶标线两侧，全部落在地形表面之上。
- `mode.training = true`：敌方**完全不向玩家开火**（跳过炮弹与导弹分支），无护甲损耗。
- 玩家高度 24，配色沿用公路/野战协调值；HUD 左下角常驻半透明操控提示卡，非训练场自动隐藏。
- 结算规则与其他模式一致：击毁全部 6 个目标（胜利）或 180s 倒计时结束（失败）。

### 10.1 状态机

```
MENU（模式选择）
  ├─ 选择模式 → PREFLIGHT（出击前检查：摄像头 / 姿态 / 手机控制器）
  │                ├─ 确认出击 → COUNTDOWN（3 秒倒计时）
  │                │                └─ PLAYING（战斗计时、敌方 AI、武器更新）
  │                │                     ├─ 清空目标 → RESULT（胜利）
  │                │                     ├─ 时间归零 → RESULT（失败）
  │                │                     └─ 玩家被毁 → RESULT（失败）
  │                └─ 返回 → MENU
  └─ 动作训练 → TRAIN（V2.5.1：出题 → 操作者做动作 → 判定 → 反复练）
RESULT → 重玩本模式（再次进入 PREFLIGHT） / 返回模式选择
```

TRAIN 阶段（V2.5.1 引入，V2.6.0 改为三通道）为**独立训练屏**：只规范操作者动作要领，**不改游戏控制映射**。菜单「动作训练」进入后，对 **5 道题**（重心左移→左转、重心右移→右转、躯干前俯→俯冲、躯干后仰→爬升、屈膝下蹲→紧急规避）× 每动作 3 次循环出题，实时信号条 + 方向判定，达标保持 0.7s 记一次通过，结算正确率；每题开始前有 1.8s 起始姿态校准并重取基准（V2.5.2）；`pose.phase='train'` 分支仅驱动该屏，不影响战斗流程。

PREFLIGHT 规则：

- 进入时立即在后台探测摄像头与姿态识别；探测期间「确认出击」置灰，避免在未就绪时误开局。
- 摄像头/姿态正常后按钮解锁，并显示「请全身（肩与髋）入镜、站直」提示，玩家可先做重心左右移/躯干前俯后仰/下蹲自检三项是否都有读数。
- 摄像头不可用或姿态加载失败时自动回退键盘模式（A/D 平移 · W/S 俯仰 · Z/X 机头），检查面板给出明确提示，仍可出击。
- 手机控制器非必需：未连接时提示「仍可开始」，连接后实时显示台数；二维码在检查面板内可直接扫码。
- 手机端在 PREFLIGHT 阶段显示「电脑端出击检查中…」，不进入倒计时。

### 10.2 主循环

`requestAnimationFrame` 驱动，dt 上限 0.1s：

1. MENU / PREFLIGHT / TRAIN 时缓慢环绕展示战场，PREFLIGHT 每 0.5s 刷新检查项，TRAIN 每帧驱动训练判定 `trainUpdate(dt)`。
2. COUNTDOWN 时倒计时（含滴答音效）、更新战机浮动，不接收武器。
3. PLAYING 时更新姿态/键盘平移、机炮节流、导弹冷却、敌方 AI、弹道、碰撞、HUD、网络同步、胜负判定。
4. RESULT 时以 0.35 倍速更新残余弹道，保留爆炸余韵。
5. 每回合重建地形/敌军/武器，并释放上一回合资源。

## 十二、通信协议（Socket.IO）

### 12.1 连接与角色

| 事件 | 方向 | 负载 |
|---|---|---|
| `join` | 客户端 → 服务端 | `'host'` 或 `'controller'` |
| `presence` | 服务端 → 全部 | `{ host: boolean, controllers: number }` |

服务端保存主机 socket、控制器集合，并在控制器加入时推送最近一次 `state`。

### 12.2 武器指令

| 事件 | 方向 | 负载 |
|---|---|---|
| `weapon` | 手机 → 服务端 → 主机 | `{ type: 'cannon' \| 'missile' \| 'flare', action: 'down' \| 'up' \| 'fire' }` |
| `weaponResult` | 服务端 → 手机 | `{ ok: true, type, action }` 或 `{ ok: false, reason: 'host-offline' }` |
| `fire` | V1 兼容 | `{ side }`，主机端视为一次机炮点射（180ms） |

- 机炮：按下发 `down`，松开/取消/页面隐藏发 `up`。
- 导弹：单击发 `fire`；手机本地 1.5s 冷却与主机冷却双重限制。
- 干扰弹（V2.2.0）：点按发 `{type:'flare', action:'fire'}`；主机按 2.5s 冷却做权威校验（数量无限），`state.flares` 以 `null` 表示无限，手机端本地 2.5s 节流并显示冷却，被拒绝时以 `weaponResult` 反馈。

### 12.3 回合状态

主机在 PLAYING 时每 400ms 发送，阶段变化（开始/结算）立即发送：

```json
{
  "phase": "menu | countdown | playing | result",
  "mode": "公路",
  "diff": "普",
  "time": 118,
  "score": 300,
  "ammo": 9,
  "armor": 2,
  "flares": null,
  "remaining": 12,
  "total": 13,
  "result": "" | "win" | "lose",
  "pitch": 12,
  "yaw": -8
}
```

服务端只向控制器广播 `state`，并缓存最后一条，供新手机加入时立即同步。`pitch`/`yaw` 为可选字段（整数角度，便于手机端显示当前姿态，V2.3.0）。

### 12.4 体感飞行姿态（V2.3.0）

| 事件 | 方向 | 负载 |
|---|---|---|
| `flight` | 手机 → 服务端 | `{ pitch, roll }`（度，已相对校准；pitch 正=抬头） |
| `flight` | 服务端 → 主机 | `{ pitch, roll, ts }`（附加服务器时间戳） |

- 服务端校验 `socket.data.role === 'controller'` 且 `pitch`/`roll` 为有限数值后转发；**不修改**原有 `weapon` 校验逻辑。
- 手机端约 15Hz 节流，且俯仰或翻滚变化超过 2° 才发送；**角度保持不变时每 0.5s 发送一次心跳**（V2.3.2），避免主机 1.2s 后判定体感失效而回落到摄像头姿态。
- **HTTPS 尝试与回退（V2.3.3 → V2.3.4）**：Chromium 系浏览器仅在安全上下文派发 `deviceorientation` / `devicemotion`。V2.3.3 曾增加 `https://<IP>:3443` 自签名证书服务，但实测华为浏览器/微信扫码无法稳定打开（证书信任被拒、3443 端口入站被 Windows 防火墙拦截），因此 V2.3.4 回退为 **HTTP 单端口 3000**，手机只负责开火，飞行姿态改由电脑摄像头识别。
- 手机端 `flight` 协议与采集代码保留，仅在未来部署到可信 HTTPS（公网域名 + 正式证书）时才有实际作用；当前主机不再依赖它。
- 主机端 `game.phonePitch / game.phoneRoll / game.phoneSeenAt` 记录最新值；新鲜度 < 1.2s 时优先于摄像头姿态作为输入，键盘始终优先。
- 主机端诊断：战斗 HUD 保留「手机体感」状态行，默认显示「未启用」；仅在收到 `flight` 数据时显示实时角度。出击前检查说明重点改为摄像头姿态识别状态（左右/前后/转身）。
- 控制器页 `controller.html` 由服务端通过 `?v=<package.json 版本号>` 提供且禁止缓存（V2.3.2），确保微信 X5 内核不会继续用旧页面；H5/JS/CSS 同样返回 `no-store`。

### 13.4 音效系统

全部使用 Web Audio API 程序化合成，无外部音频文件；首次点击/按键后解锁 AudioContext。

| 事件 | 音效 |
|---|---|
| 机炮开火 | 短噪声 + 下滑方波，按 42ms 节流 |
| 导弹发射 | 带通噪声 + 上升锯齿（推进感） |
| 锁定目标 | 两声高音 ping |
| 机炮命中 | 高频金属撞击 | 
| 爆炸（击毁 / 拦截 / 玩家被毁 / 敌弹落地） | 低频噪声 + 低音轰鸣，按距离衰减 |

| UI 操作 | 短促点击音 |

- 音效开关持久化于 `localStorage`（`mj.sound` = `1`/`0`）。
- 同类音效带最小触发间隔，避免高速连射时音轨叠加过载。

### 14.1 程序化模型

- 玩家战机：机身、座舱、后掠翼、双发动机、左右机炮口、机腹导弹挂架、尾焰发光。

- 全部材质为低多边形纯色/顶点色，无外部贴图依赖。

### 14.2 地形与特效

- 地形：620×620、120×120 段、Perlin/fbm 高度、顶点色按高度/坡度着色、平滑法线。
- 公路：沿曲线生成 ribbon 几何 + 白色虚线 InstancedMesh。
- 植被：锥形树与岩石实例化，减少 draw call。
- 海面：顶点波动 + 周期法线重算，配合雾与日光。
- 云层：Canvas 生成云纹理的 Sprite，多个高度层缓慢漂移。
- 光照：半球光 + 平行光阴影（1024 PCFSoft）、ACESFilmic 色调映射、各模式雾。

### 14.3 性能策略

- 像素比上限 2；阴影仅主要单位投射。
- 树木/岩石实例化；弹丸池化复用几何与材质。
- 回合切换释放地形、模型、材质与弹道，防止显存泄漏。
- 目标：1080p 下 ≥50fps；需在目标真机上实测确认（本期自动化测试未做帧率基准）。

### 15.2 人工验收建议

1. 电脑打开 `http://localhost:3000/`，允许摄像头，确认姿态左右移动可控制战机。
2. 选择模式后进入出击前检查：确认摄像头画面、姿态状态灯、手机连接数与二维码，确认后才开始。

5. 试听全部音效并用右下角按钮关闭/开启，确认关闭后无声音且刷新后保持设置。
6. 验证边界：导弹打空扣分、机炮打空扣分、导弹耗尽、分数不低于 0；键盘 E 双发导弹余量 10→8、F 双发干扰弹。

## 十六、已知限制与注意事项

1. 模型为程序化低多边形写实风格，追求辨识度与性能，不是照片级。
2. 无存档、无排行榜。
3. 音效由 Web Audio 合成，浏览器要求首次用户手势后才能出声（点击模式卡即已解锁）。
4. 敌方 AI 为巡逻/ convoy/盘旋 + 周期开火，未做复杂战术规避。
5. 导弹为弱制导，快速机动目标可能脱靶。
6. 摄像头姿态依赖光线与全身入镜；识别丢失会锁定当前位置。
7. 华为等手机若无相机扫码入口，请使用微信扫一扫（已验证）。
8. 手机与电脑必须同一局域网，且电脑服务端保持运行。
9. 第二阶段未实现：GitHub 部署、多用户、多战机；GitHub Pages 无法承载 Socket.IO 服务端。
